# 运行日志优化实施与验证

## 范围与验收

1. 网格卖出受限时不生成重复信号；会话保持运行，买入继续遵守原有风控；可卖恢复后重新评估当前价格，执行端继续限制数量。
2. 本地委托超时检查周期集中配置为 3 秒，并观测超过截止时间的处理延迟；沿用连续交易时间口径。
3. 净值恒等式异常最多复查一次，保留原始观察记录；持久化差额、质量状态和采集时间，并随交割单导出。
4. 定时同步和 Timer 重试串行运行；保留重试上限，观测最近成功时间和同步耗时。
5. 生命周期日志包含发布版本和启动时固定的源码摘要，交易日志区分提交与成交。
6. 日志清理在到点后每日执行一次，错过指定分钟和暂时失败后可补执行。

## 验证方法

- 所有测试均在 `logs/runtime_optimization_20261019/workspace/` 的隔离源码副本内执行。
- 使用 Python 3.9、模拟配置、虚构账号及测试数据库；不复制生产配置、生产数据库或运行日志。
- 新增专项回归先对修改前源码运行，再对最终源码运行。
- 最终执行 `test/run_integration_regression_tests.py --all-with-fast`，要求失败、错误和跳过均为零。
- 测试结束核对源码摘要，再只提交本次变更；保留工作区原有的 `CLAUDE.md` 修改。

## 配置与数据兼容

| 配置 | 默认值 | 用途 |
|---|---|---|
| `PENDING_ORDER_CHECK_INTERVAL_SECONDS` | 3.0 秒 | 扫描本地委托，仅超时后查询柜台 |
| `SETTLEMENT_ASSET_RECHECK_COUNT` | 1 | 净值异常时额外取数次数 |
| `SETTLEMENT_ASSET_RECHECK_DELAY_SECONDS` | 0.2 秒 | 净值复查间隔 |
| `LOG_CLEANUP_CHECK_INTERVAL` | 60 秒 | 每日清理检查间隔 |

净值表通过幂等补列增加 `identity_diff`、`validation_status`、`observed_at`。
`validation_status` 为 `valid`（通过）、`pending_review`（待核对）或
`unverified`（未核验）；历史行保持未核验，不伪造采集时间。复查原始观察保留在
`run_events`，有效原始总资产不以分项求和替代。导出 CSV 在原有列后追加质量字段，
旧库未迁移时仍可只读导出，质量显示为未核验。

生命周期的 `code_id` 是项目根目录 Python 源码的摘要，在进程内固定；
代码更新后应通过正常重启加载新实现和净值补列，本次不操作运行中的交易进程。
