# 持仓可卖数量与冻结告警优化开发计划

日期：2026-10-19

状态：已完成开发及完整集成回归；38 组、167 个模块、3,711 项全部通过，验证结果见 [交付记录](2026-10-19-sellability-delivery.md)。

基线：`7e2cce54`，关联 [运行日志审查](2026-10-19-runtime-log-review.md)。

## 1. 目标与边界

目标：交易按最新可卖数量执行，正常 T+1 冻结不被当作系统故障，无法卖出的止损风险仍能及时告知，Web 能解释总数与可用的差额。

基本口径：

- 总数用于持仓、仓位占用、风险敞口和盈亏计算；可用用于卖出数量上限。
- `总数－可用` 表示不可卖数量，不能直接全部认定为当日买入数量。
- 普通 A 股当日买入可造成 T+1 受限；未完成卖单、其他冻结与数据延迟也可能造成差额。
- 券商最新持仓是可卖数量的权威来源；委托提交成功不等于成交成功。
- 成交证据使用已成交记录，不能使用买入委托的申报数量冒充当日买入数量。

本期覆盖 miniQMT 动态止盈止损、网格卖出、XtQuantManager 自动止盈止损，以及 web1.0/web2.0 持仓展示。IPC/RPC 等通道遵守相同可卖数量上限；缺少诊断字段时显示原因待确认。

本期不扩展证券品种结算规则，不改变既有止损价格、止盈比例和网格档位算法，不建立新的交易状态机框架，不迁移数据库。缠论选股调度器不属于本期修改范围。

## 2. 请评审的业务决定

| 编号 | 决定项 | 推荐行为 | 其他可选行为及影响 |
|---|---|---|---|
| D1 | 首次止盈比例基准 | 沿用当前设计：按最新可用数量乘止盈比例 | 按总数乘比例后再受可用上限约束；可能卖出更多可卖股份，属于策略规则变更 |
| D2 | 止损成立但股份受限时的新增买入 | 暂停该股自动补仓和网格买入；仍允许合法的风险卖出 | 只阻断卖出，买入规则不变；可能在无法卖出时继续增加持仓 |
| D3 | 次日可用数量恢复后的处理 | 用最新价格、成本、配置重新判断，条件仍成立才下单 | 保留跨日强制退出意图；即使原条件已经消失也卖出，需要新增明确的退出规则和持久化设计 |

D1 示例：总数 2,000 股、可用 1,000 股、止盈比例 60%。推荐口径卖出 600 股；另一口径的计划量为 1,200 股，受可用限制后最多卖出 1,000 股。

D2 推荐的暂停是临时执行门控，不修改网格会话的 `enabled`。止损条件消失且数据可靠后解除临时门控；已有的成交后持久暂停规则仍按原逻辑处理，不自动恢复人工暂停的会话。

D2 遵守动态止损总开关和个股开关。网关自动卖出限定在真实连续竞价时段，休市期间不消耗防重额度，也不执行旧的跨日意图。

本次实施采用 D1、D2、D3 推荐行为。跨日处理重新取得价格和持仓，不建立跨日强制退出意图。

## 3. 持仓状态与报警规则

| 状态 | 判定依据 | 交易处理 | 通知处理 |
|---|---|---|---|
| 正常可卖 | 持仓数据有效，数量关系合法，无已知受限部分 | 按最新可用数量执行 | 不增加冻结通知 |
| 已确认 T+1 受限 | 适用 T+1 的股票，有可核验的当日买入成交，持仓与委托信息足以解释受限原因 | 部分可卖时允许卖出；全部受限时不提交卖单 | 首次或状态变化时记录信息；稳定状态放入界面和心跳摘要 |
| 卖单占用 | 有已确认接受且未终结的卖出委托 | 阻断重复下单，等待成交或撤单确认 | 状态提示；只有超时或状态异常才升级告警 |
| 混合受限 | 同时存在当日买入受限与卖单占用证据 | 对可确认的剩余可卖部分执行原策略 | 展示两类原因，无法拆分的数量如实标为待确认 |
| 原因待确认 | 查询失败、字段缺失、数据陈旧或差额无法解释 | 执行前不能取得可靠可卖数量时阻断自动卖出并安排刷新 | 按异常原因节流告警，不显示为已确认 T+1 |

任何状态下，只要价格达到止损条件，都继续检测和记录风险。全部受限时首次告警示例：

> 已触发止损，当前可卖 0 股，受限持仓 1,500 股，原因为已确认 T+1；继续监控，下一交易日刷新后重新判断。

同一风险状态不按轮询周期重复打印；风险首次出现、原因改变、可卖数量改变或风险解除时输出对应事件。正常冻结不自动升级为“请人工确认”。委托超时和数据查询异常保留原有告警责任。

## 4. 数据与实现约束

### 4.1 最小数据扩展

保留现有 `volume`、`available`，新增兼容字段供 API 和界面使用：

| 字段 | 含义 |
|---|---|
| `unavailable_volume` | 有效数量差额；数据缺失或非法时为 `null`，不能用 0 冒充已确认 |
| `restriction_reason` | `none` / `t1` / `sell_order` / `mixed` / `unknown` |
| `restriction_detail` | 后端生成的中文解释；未核实的具体受限数量不作确定陈述 |
| `position_asof` | 最近一次成功取得券商持仓的时间；价格刷新时间不能代替它 |

QMT 的冻结、在途、昨仓字段先核对实际通道口径，再作为证据接入。网关当前将差额命名为“冻结数量”，不能直接把这个字段解释为 T+1 数量。分类只使用已有同步结果和批量取得的当日委托、成交数据，不在每次 Web 刷新或每股每轮检测时新增券商查询。

建议在现有 `order_utils.py` 中增加一个小型纯函数，统一数量合法性和原因分类；各通道负责提供证据。函数不访问数据库、不调用券商接口、不创建线程。字段不足时返回 `unknown`，不添加多层服务或规则引擎。

### 4.2 卖出执行约束

- 所有自动卖出入口在提交前校验可靠的最新可用数量，保留 `validate_trading_signal()` 的统一验证责任。
- 最新可用明确为 0 时返回“暂不可卖”，不能回退到旧信号数量；查询失败与明确的 0 分别报告原因。
- 止损、动态全仓止盈按当前可卖范围执行；首次止盈按 D1 计算，并遵守证券的整手及零股规则。
- 不能使用 `max(100, ...)` 将 0 或不足可卖数量强行变成 100 股卖单。
- 数量字段缺失时不能回退为总持仓，特别检查网格和兼容通道中的此类回退。
- 券商可用通常已反映挂单占用；本地预占只保护尚未反映到券商快照的提交窗口，按委托身份核对，避免重复扣减同一卖单。
- 冻结或数量不足不计为已执行，不消耗交易成功标记；网关防重时间不能在可卖检查前写入，导致数量恢复后仍被旧冷却阻断。

### 4.3 生命周期约束

- 只有券商确认总持仓为 0，才报告“已清仓”；卖完可用但仍有总持仓时报告“可卖部分已成交，仍有受限持仓”。
- 受限期间继续更新价格、风险和最高价，不停止整个持仓监控线程。
- 跨交易日以交易日历和新券商快照恢复判断，不在午夜强制执行 `available = volume`，不复用昨日价格下单。
- 运行状态按账号、股票和交易日隔离。共享状态使用锁保护；慢速查询和下单放在锁外；回调线程内不反向等待 QMT 同步接口。
- 派生字段优先随 API 计算，不增加数据库列；如缓存其状态，状态变化必须使数据版本更新，保证 Web 能刷新。
- 新增可调阈值统一放入 `config.py`；优先复用现有持仓查询间隔和日志节流配置。

## 6. 必须覆盖的回归场景

| 场景 | 验收结果 |
|---|---|
| 当日买入后总数大于 0、可用为 0 | 确认原因后显示 T+1；止损仍可通知；主程序和网关均不提交卖单 |
| 昨仓与今日买入混合，可用大于 0 | 按 D1 和最新可用计算数量；冻结不影响正常的可卖部分 |
| 网关首次止盈时可用为 0 或不足最小计划卖量 | 不强行构造 100 股订单，不提前更新执行成功标记 |
| 校验后、下单前可用从正数变为 0 | 阻断提交，不退回旧信号量；可用恢复后重新验证 |
| 存在未完成卖单，但当天没有买入 | 显示卖单占用，不误报 T+1，不重复卖出 |
| 当日买入与未完成卖单同时存在 | 能解释的部分分别展示；不能解释的部分保留待确认 |
| 本地预占随后被券商快照反映 | 同一委托不重复扣减；不发生超卖或永久假性无可卖量 |
| 查询失败、字段缺失、旧 SQLite 快照或非法数量 | 不认定为已确认 T+1，不用总数替代可用；出现明确的数据状态提示 |
| 止损成立且只有冻结股份 | 按 D2 门控新增自动买入；保持价格和风险监控 |
| 卖完可用但冻结股份仍在 | 展示剩余受限持仓，不报告已清仓，不停止风险监控 |
| 撤单确认、成交回报、重复或延迟回报 | 不重复下单，更新占用状态，不破坏异步重挂保护 |
| 周五买入后跨周末或节假日 | 不按自然日解冻；下一交易日刷新后按 D3 重新判断 |
| 进程重启、不同账号持有相同股票 | 从新快照恢复状态；账号之间不串用原因、告警或冷却记录 |
| 冻结状态保持、变化、解除后再次出现 | 稳定状态不刷屏；关键变化及时通知；真实查询异常仍能告警 |
| Flask、网关、IPC/RPC 及旧版 API 响应 | 数量上限一致；缺失原因字段安全降级；原持仓列仍可正常显示 |

## 7. 回归环境与完成标准

- 隔离副本启动前准备虚构的 `account_config.json`，禁用本地 `.env` 加载；初始 `ENABLE_SIMULATION_MODE=True`。
- 对实盘分支的验证使用 Mock 券商接口，不连接真实交易账号，不启动生产交易进程，不改生产数据库。
- 现有模拟盘当日买入立即可卖的行为不在本期改写；T+1 用例明确构造受限持仓，避免用模拟盘现有行为代替实盘验证。
- 券商字段语义无法从现有接口、测试和只读样本确认时，先保留 `unknown`，不以猜测填充。
- 完成标准：所有新增复现用例与必要回归通过，模块全部加载；零未解决失败、零测试错误；跳过项如有必须说明。
- 交付报告说明实际测试数量、执行环境、异常及复测记录，并核对测试副本与交付代码一致。不能仅凭测试运行器退出码判定全部通过。

交易执行审查补充：网关防重与成交确认分开处理；旧价格缓存不得靠复用自身延长有效期；模拟卖出全部可用股份后仍须保留受限余仓。集成回归必须全部通过后才提交和推送。
