# 持仓可卖数量与冻结告警优化交付记录

## 交易执行审查结论

采用开发计划中的三个推荐行为：首次止盈按最新可用数量计算；止损条件成立且持仓受限时，临时阻断该股新增自动买入；次日依据新价格、新持仓和当前配置重新判断，不重放昨日信号。

总持仓与可用数量不一致本身不是故障。只有券商持仓、当日买入成交和活跃卖单能够解释差额时，才显示已确认的 T+1 或混合受限；未知原因保留待确认。ETF 等未明确结算规则的品种不依据股票规则推断 T+1。

## 最终行为

- 动态止损、首次止盈和全仓止盈执行前重读可卖量。明确为零、字段缺失、读取失败或实盘快照过期时阻断，不能回退到旧信号量。
- 网关首次止盈不会把零可卖量放大为 100 股。数量按整手口径计算，剩余零股卖出不超过可用量。
- 委托受理、在途防重和成交确认分别处理。网关确认真实成交后才推进首次止盈标记；拒单不保留虚假的成功冷却。
- 网关自动卖出遵守真实连续竞价时段。缓存价格不能通过反复复用延长自身有效期。
- 受限股份触发止损时发出风险通知；稳定的正常冻结不按轮询频率重复告警。可用数量恢复后重新评估。
- 自动补仓和网格买入遵守临时风险门控，人工买入仍由人工决定；门控不修改人工网格启停开关。
- 自动买入客户端带自动请求来源标记，Web 买入 API 再检查受限止损，关闭持仓防重也不能绕过；原手动买入 API 行为保留。
- 网关客户端和 IPC 不把缺失的可卖数量回退为总持仓。查询异常时停止本次卖出。
- 卖出本次全部可用股份后，仍有受限持仓时保留余仓，不报告已清仓；继续监控风险。
- web1.0 与 web2.0 显示不可卖数量、受限原因和券商持仓核对时间。接口旧字段兼容，缺少诊断信息显示待确认。

受限状态取数复用持仓同步时批量取得的当日成交和委托；网关证据缓存按现有持仓查询间隔更新。未新增数据库表或迁移，未修改生产配置和运行进程。
